Service (in-cluster):
  https://{{ include "ubixvault.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}
{{- if not .Values.tls.enabled }}

  ⚠  TLS is DISABLED. Secrets are served in the clear{{ if .Values.devNoTLS }} (devNoTLS){{ end }}.
     Do not use this outside a trusted network.

1. The vault starts SEALED and must be INITIALIZED once. Run init inside the pod:

     kubectl -n {{ .Release.Namespace }} exec -it {{ include "ubixvault.fullname" . }}-0 -- \
       ubixvault operator init -shares 5 -threshold 3

   SAVE the unseal shares and the root token it prints — they are shown once.

{{- if .Values.autoUnseal.enabled }}

2. Auto-unseal is ENABLED: after init, the pod unseals itself on every restart
   using the KEK from Secret "{{ include "ubixvault.autoUnsealSecretName" . }}".
   Protect that Secret — it can unseal the entire vault.
{{- else }}

2. Auto-unseal is DISABLED (Shamir): after init, and after every restart, unseal
   by providing a threshold of shares:

     kubectl -n {{ .Release.Namespace }} exec -it {{ include "ubixvault.fullname" . }}-0 -- \
       ubixvault operator unseal <key>   # repeat until sealed=false

   The pod stays NotReady until unsealed (readiness probe gates on 200).
{{- end }}

3. Check status:

     kubectl -n {{ .Release.Namespace }} exec -it {{ include "ubixvault.fullname" . }}-0 -- \
       ubixvault operator seal-status

{{- if .Values.kubernetesAuth.enabled }}

4. The Kubernetes auth method is ready: this release's ServiceAccount is bound to
   system:auth-delegator, so the vault can validate pod ServiceAccount tokens.
{{- end }}
